# Contact identity and group-request batch queries

`getUserProfile(userId)` resolves the requested UID and reads the native profile Map. Both `coreInfo.uid` and `coreInfo.uin` must be strings and exactly match the resolved UID and requested numeric user ID. Missing identities, contradictory identities, numeric/object UIN values and array-shaped profiles reject. The SDK does not invoke `toString()` to manufacture an identity. Valid identifiers preserve their original decimal bytes, including leading zeroes. Nickname/remark defaults and the original `raw` profile remain unchanged.

The fixed upstream CoreInfo declaration requires string UID/UIN: [NapCatQQ user types](https://github.com/NapNeko/NapCatQQ/blob/26d7533e0f5800fdff865ab2f2ad7692917e1076/packages/napcat-core/types/user.ts). Local raw bytes were independently checked against Git blob `669f23389834cd7a2fa05743bd8726423bacc6df`.

Group-request pages and unsolicited notification updates validate every array entry before emitting actionable requests. Sparse slots are materialized and rejected as malformed notifications; a valid prefix cannot become a partial success or pollute event deduplication. Existing filtering of non-actionable notice types, successful empty pages and dense valid pages remain supported. A failed dispatched page still invalidates the uncorrelated query channel; another list request requires a new Session and is not automatically retried.

Three new regressions fail on the previous source and pass after the fixes.
