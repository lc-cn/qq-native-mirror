# History queries and client lifecycle

The unpublished source captures `getHistory(peer, options)` before IPC and before private-peer UID resolution. The public options remain `before?: string` and `limit?: number`: a decimal-string cursor (default `'0'`) and an integer count from 1 to 100 (default 20). Numeric strings retain leading zeroes and arbitrary precision. Inputs are captured and copied, so later caller mutation cannot change the requested conversation, cursor or count.

The worker also captures these values. Existing JavaScript compatibility options `messageId`, `count` and `reverse` remain accepted at runtime: cursor/count aliases must agree if both are defined; `reverse` must be a boolean and defaults to false. Undefined optional values use defaults. Invalid types, conflicting aliases, accessors and unsupported option keys reject before query service acquisition or UID lookup. This validation is SDK policy; it does not claim an independently observed native limit. Native ordering and successful empty results remain unchanged; native errors and malformed or mismatched records reject the query.

`getMessage`, `getMessages` and `getHistory` now observe Session shutdown while awaiting a native Promise. Close rejects these observations promptly even when the native Promise never settles. A late result or rejection is observed without replay, decoding or delivery. The SDK cannot cancel an already dispatched native/server request. Responses are checked against a separately retained conversation identity, so mutation of the native call argument cannot make a different conversation appear valid.

`waitForLogin()` joins a pending login without issuing another authentication request. Once online, it returns a fresh copy of the currently stored account identity instead of the mutable result of an old completed Promise. Calls while closing/closed reject; a different configured default account does not replace the current identity returned by this wait method.

CLI watch supports both `autoReconnect: true` and an object policy such as `{ maxAttempts: 2, delayMs: 1000 }`. Only an explicitly retryable disconnect can keep watching under an enabled policy. Unknown disconnects, kick/logout, termination and reconnect errors still stop watch. This does not add a new safely retryable native reason or prove server restoration. Invalid watch policies fail before native preparation.

The CLI compares the real entrypoint path with its module URL. This permits npm's POSIX `.bin` symlink and macOS temporary-directory aliases to execute the installed CLI. Importing the CLI from another program does not execute it. Source subprocess regressions cover canonical paths, symlinks, preflight failures and imports; clean installed-package validation also invokes npm's actual POSIX binary link.

The shared consumer contract uses controlled Workers and services only, including three never-settling native-read substitutes. It runs against source and clean installed compiled code. These checks perform no actual login, restore, message read/send, recall or signature request. Actual native account acceptance and signing authenticity remain separate requirements. See [bound local evidence](evidence/history-lifecycle-local.json); six-platform evidence for this source must be recorded separately from earlier resource-reader CI.
